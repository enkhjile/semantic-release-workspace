# Manifest preparation and durable publication

Implement the authorized publishing milestone for Node 24+. Keep the planner and existing batch tag contract. Production defaults to publication; `publish: false` retains planning-only operation and all existing fixtures opt into it. No public registry is contacted in tests.

Freeze the plan and publishing destinations before changing files. Prepare canonical JSON and comment-preserving TOML manifest edits, including inherited Cargo versions, local dependency ranges, and npm publish protocol conversion. Package tags identify a detached prepared commit containing released manifests; the source branch remains unchanged. Restore original manifests after success/failure. Recovery may restore only exact plugin-owned prepared files, never arbitrary user edits. Dry runs perform validation and planning only: no manifest writes, artifacts, journal pushes, package tags or registry writes.

Retain the prepared commit and exact immutable package artifacts in dedicated Git refs reachable from the release journal. Before uploading each artifact, persist an intent. Query the destination version and compare registry integrity/checksum with that exact artifact. Only a matching version backed by this journal's intent may be recovered as published. Authentication, network errors, mismatches and foreign existing versions fail closed. Persist progress after each publication and tag; replay exact bytes from a fresh clone. Package tags are never moved. Native npm packing, official npm publishing/configuration/transport libraries with an origin-bound agent, and native Cargo package verification are used; Cargo upload uses its documented registry web API to transmit the retained .crate bytes without repacking.

Use dependency-first plan groups; npm cycles are permitted, cyclic Cargo publication is rejected before effects. Private packages are prepared but never uploaded/tagged. npm uses configured or package/native registry/access settings. Cargo supports crates.io and named HTTP sparse registries, publish allowlists, standard token environment variables/credentials files; unsupported credential-provider-only or git-index configurations fail with actionable errors. Do not log subprocess output, authenticated URLs or tokens. Registry redirects must not forward credentials to another origin.

Schema 3 adds prepared commit/ref, destination policy, artifact refs/digests and per-package intent/publication/tag states; schema 1/2 remain readable. Config or prepared/artifact corruption must block retry. Completion advances version baselines only after publication, package tagging and restoration succeed. Artifact refs are durable release state and must be retained/backed up. Large artifacts are limited to 100 MiB for Git-backed retention.

Verify using real semantic-release processes, disposable bare remotes, a local npm-compatible registry and local Cargo sparse registry/API. Exercise packed contents, real Cargo verification, private packages, workspace protocols, dependencies, dry runs/no-change, rejected writes, accepted uploads with lost responses, fresh-clone retry, tag conflicts, artifact/state corruption and dirty-checkout protection.


Implementation refinements from independent review: npm artifact manifests and all package scripts run in isolated Git-aware copies; source canonical manifests use same-filesystem atomic replacement with temporary files under the Git directory. Recovery checks every ancestor for symlink changes. Staging projects all native ignored entries, including local info/exclude and global excludes, into rooted escaped rules. The npm transport freezes scope routing, native access (including null/no-change) and tag, and retains scoped TLS cert/key and CA/proxy configuration. Consumer OIDC/provenance is deferred. npm runtime clients are the latest stable releases compatible with the declared Node 24.0 floor; newer client majors require 24.15+.
