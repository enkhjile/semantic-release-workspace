# npm OIDC and retained provenance

Extend the existing real semantic-release plugin. Preserve Node 24.0+, Cargo publishing, immutable tarball refs, write-ahead intents and origin-bound registry transport. The user authorized implementation, dry-run/retry safety and real-core integration tests.

`npm.trustedPublishing` accepts `auto` (default), true (required) or false (configured npm credentials). Auto selects OIDC when supported CI identity is available. Support GitHub Actions identity requests and NPM_ID_TOKEN for GitLab/CircleCI. Once selected, exchange failure is an error, never a silent fallback to another credential. Exchange each package separately, immediately before upload; keep ID and exchanged tokens only in memory and never use publish tokens for read probes. CI and exchange redirects are rejected. Freeze effective authentication policy with the destination.

`npm.provenance` accepts auto (default), true or false, with package/native npm configuration honored. Auto signs public packages from public GitHub/GitLab repositories using OIDC; explicit true requires supported CI, matching source SHA, public package/repository and Sigstore identity. CircleCI OIDC is supported without automatic provenance; explicit provenance is rejected there. Dry runs validate policy without fetching identity, exchanging tokens, signing, writing refs or uploading.

Use the official Sigstore SDK, an npm-compatible SLSA/in-toto statement with the exact tarball SHA-512 and npm PURL, and authenticated public-good Fulcio/Rekor services. A small local forwarding gateway makes SDK signing requests with redirect rejection because the current SDK does not expose an origin-bound transport. Public trust is obtained through the official TUF verifier. Optional explicit npm.sigstore settings support private instances (Fulcio/Rekor URLs and TUF mirror/root); defaults remain Sigstore public-good services. Credentials never enter those settings or durable state.

Sign and verify before retaining an artifact or recording upload intent. Persist the public Sigstore bundle with the tarball metadata in the immutable artifact commit. On retry, reuse and verify its exact bundle; never rebuild, re-sign or mislabel retained artifacts with a later CI run. Existing schema-3 token-mode states remain readable. New policy fields are included only when enabled, preserving completed and pending old token batches.

Publish the exact npm registry PUT representation with tarball and .sigstore attachments; use npm's official registry configuration/auth/transport for credential and TLS compatibility. The provenance path constructs the documented npm attachment representation so it can submit the already verified retained bundle, without forcing opaque native-client re-signing. Normal token publishing retains its existing native client path. Confirm provenance publication using the registry's attestation endpoint as well as tarball integrity. Missing, different or malformed provenance keeps the batch pending; an accepted uncertain upload can finish from a fresh clone without new OIDC/signing calls.

Test with real semantic-release child processes and local registry/CI HTTP services; use official Sigstore cryptographic fixtures plus a signed local TUF repository. Verify two package-scoped exchanges, required-mode failures, no fallback or token persistence/log leaks, dry/no-change zero side effects, native auth compatibility, signed payload/digest/source identity, accepted/rejected upload retries, exact fresh-clone bundle reuse, attestation mismatches/corruption, expired credentials and redirect rejection. No public publication or Sigstore ledger writes in tests.
